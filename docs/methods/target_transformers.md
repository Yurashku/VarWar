# Трансформации метрики и target

`TargetTransformer` не оценивает эффект самостоятельно. Он формирует новый
target, после чего запускается совместимый estimator. `MetricTransformer`
работает ещё раньше: меняет исходное определение метрики.

## CUPED в VarWar

ID: `cuped`. Реализация: `CupedTransformer`.

$$
Y^*=Y-\theta(X-\bar X),\qquad
\theta=\frac{\operatorname{Cov}(Y,X)}{\operatorname{Var}(X)}.
$$

Обычно $X$ — значение той же метрики до эксперимента, но это может быть любая
заранее измеренная числовая ковариата. Модель машинного обучения не нужна.
Источник коэффициента задаётся явно параметром `fit_data`.

Основной локальный вариант `cuped_control` оценивает коэффициент и среднее
ковариаты на контроле текущего эксперимента, затем одинаково преобразует обе
группы. Отдельная обучающая выборка ему не нужна. Режимы `experiment_all` и
`reference` доступны в общем движке только как явные политики.

При pre-treatment $X$, одинаковом преобразовании обеих групп и корректном
центрировании CUPED сохраняет исходный ATE в математическом ожидании. Оценивание
коэффициента на том же эксперименте требует проверки конечновыборочного
смещения, FPR и покрытия на синтетике.

Важно: `cuped_control__hypex_ab` использует **CUPED VarWar**, затем HypEx Welch
A/B. Это не вызов нативного `hypex.CUPEDTransformer`.

Нативный `hypex.CUPEDTransformer` из проверенного PyPI HypEx 1.0.6 также
использует стандартный коэффициент `Cov(Y, X) / Var(X)`, но оценивает его на
всех строках переданного `Dataset`: отдельной фильтрации только по control в
этом transformer нет.

## CUPAC в VarWar

CUPAC использует прогноз $m(X)$ как control variate. Отличие от CUPED не в
самой идее вычитания шума, а в способе получить ковариату:

- CUPED обычно берёт один готовый pre-target;
- CUPAC обучает прогностическую модель по набору признаков;
- линейный CUPAC может быть близок к многомерному CUPED;
- нелинейность зависит от выбранной модели, а не от названия CUPAC.

### Локальный temporal CUPAC A

ID движка: `cupac_linear`. ID политики: `cupac_linear_A`.

В одном доступном датасете для каждой строки должны присутствовать значения
признаков за два предшествующих периода:

1. модель ridge обучается на переходе `lag2 features → lag1 pre-target`;
2. эта же модель получает `lag1 features` и прогнозирует шум текущего target;
3. из текущего target вычитается центрированный прогноз;
4. текущий outcome не участвует в обучении модели.

Такой контракт использует временную структуру внутри одного набора строк и не
требует отдельной historical-выборки. Коэффициент перед центрированным
прогнозом равен единице: модель непосредственно прогнозирует ожидаемую часть
target.

### Интеграция HypEx CUPAC

ID конвейера: `hypex_cupac_temporal`. Текущий адаптер VarWar явно задаёт
`cupac_models="linear"`, поэтому эта строка **линейная**, не нелинейная.

Для target и каждого временного признака нужны lag-1 и lag-2:

1. lag-2 признаки и target используются для прогноза lag-1 target;
2. модель обучается на lag2/lag1-парах того же доступного датасета;
3. только lag-1 признаки подаются модели для прогноза текущего target;
4. по текущему target и прогнозу на всех строках HypEx оценивает
   $\theta=\operatorname{Cov}(Y,\hat Y)/\operatorname{Var}(\hat Y)$;
5. из target вычитается $\theta$ умноженная на центрированный прогноз;
6. на фактически преобразованном target выполняется Welch A/B-анализ.

Это важное отличие от локального `cupac_linear_A`, где коэффициент перед
прогнозом фиксирован и равен единице. Если PyPI HypEx недоступен, совместимый
fallback `hypex_cupac_temporal` повторяет и temporal-модель, и оценивание theta.

При `cupac_models=None` сам HypEx может выбирать среди linear, ridge, lasso и
доступных нелинейных моделей. VarWar этого режима сейчас не использует.

### Зоны A, B и C

Это три отдельных примитива и три последовательных пайплайна:

- `cupac_linear_A`: temporal CUPAC только на pre-treatment признаках;
- `cupac_linear_A_plus_B`: результат A, затем отдельная линейная корректировка
  по экспертно разрешённым in-time признакам B;
- `cupac_linear_A_plus_B_plus_C`: результат A+B, затем отдельная линейная
  корректировка по допущенным признакам C.

B и C **не добавляются в модель A**. Для каждой из этих зон линейная модель
обучается по текущему контролю уже на target, скорректированном предыдущими
этапами, и затем применяется к обеим группам.

Обычный Welch после такого преобразования не учитывает неопределённость
обучения B/C и адаптивность C-gate. Поэтому оба варианта считаются
исследовательскими до реализации cross-fitting или отдельной поправки
дисперсии.

Для C одного баланса недостаточно. До автоматической проверки из списка
должны быть исключены производные outcome, признаки с утечкой и возможные
медиаторы. После этого код проверяет:

- абсолютную стандартизованную разность средних;
- разность долей пропусков;
- KS-расстояние между группами.

Не прошедший пороги C-признак отбрасывается или вызывает ошибку согласно
`failed_gate`. Прохождение gate является диагностикой, а не доказательством
причинной безопасности.

Внутри реализации используются `CupacFeaturePolicy`,
`LinearCupacTransformer`, `LinearInTimeAdjustmentTransformer` и
`SequentialTargetTransformer`; линейная алгебра не дублируется.

### Ограниченный нелинейный CUPAC

`cupac_quadratic_A` расширяет только зону A квадратами и попарными
произведениями признаков. Обучение остаётся temporal `lag2 → lag1`, а ridge
ограничивает неустойчивость. Число модельных колонок равно
$p+p(p+1)/2$, поэтому этот вариант допускается в гонку лишь при умеренном
числе признаков. Общий `nonlinear_cupac` пока остаётся R&D-заглушкой.

## Робастные преобразования

| ID | Смысл | Влияние на estimand | Статус |
| --- | --- | --- | --- |
| `winsorized` | Ограничить target квантилями текущего контроля | меняет целевую метрику | реализован |
| `trimming` | Удалить хвосты по заранее заданной политике | меняет популяцию и метрику | заглушка |
| `robust_cuped` | Робастно оценить CUPED-коэффициент | должен сохранять ATE при честном fit | кандидат R&D |
| `cupac_quadratic_A` | Квадратично прогнозировать шум по зоне A | должен сохранять ATE | реализован, исследовательский |
| `nonlinear_cupac` | Общая нелинейная модель за пределами квадратичного варианта | пока не зафиксировано | кандидат R&D |
| `bayesian_cupac` | Байесовская прогностическая коррекция | пока не определено | низкоприоритетная заглушка |

`robust_cuped` не следует называть общим «robust estimation»: это конкретный
способ защитить коэффициент control variate от тяжёлых хвостов. Его преимущество
не гарантировано и должно проверяться по bias, RMSE, FPR и power.

## Ratio-метрики

`ratio_delta` уже выполняет прямое оценивание ratio-of-means и строит
delta-method inference; t-test поверх него не требуется.

`ratio_linearization` — отдельный планируемый `MetricTransformer`. Он должен
создать аддитивный пользовательский target, сохранить правило обратного
масштабирования и затем позволить композицию:

```text
ratio linearization → CUPED/CUPAC → estimator
```

До фиксации опорного отношения, правила восстановления масштаба эффекта и
расчёта дисперсии этот компонент остаётся неисполняемой заглушкой.
