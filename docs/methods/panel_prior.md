# CUPAC с априорной информацией из исторической панели

## Назначение

`panel_prior_cupac_A`, `panel_prior_cupac_A_plus_B` и
`panel_prior_cupac_A_plus_B_plus_C` являются вариантами `TargetTransformer` для
рандомизированного эксперимента. Они не добавляют строки исторической панели в
эксперимент и не используют идентификаторы клиентов. Историческая панель
передаётся только как агрегированные достаточные статистики.

У метода два независимых режима доступа:

- `experiment_only`: доступна только панель РКИ и её разрешённые pre/in-time зоны;
- `panel_prior`: дополнительно доступен агрегат исторической панели, построенный
  до даты начала эксперимента.

Первый режим не требует `PanelPriorSummary`. Второй не разрешает смешивать
исторические наблюдения с экспериментальными при расчёте эффекта.

## Контракт `PanelPriorSummary`

`PanelPriorSummary.from_frame(...)` принимает локальный датафрейм для синтетики
и R&D. Внутренний контур должен поставлять эквивалентный объект из SQL-запроса
по таблице `entity_id × report_date` с месячной гранулярностью.

Минимальный контракт запроса:

```sql
SELECT
    report_date,
    COUNT(*) AS n_rows,
    COUNT(DISTINCT entity_id) AS n_entities,
    SUM(y_pre) AS y_sum,
    SUM(y_pre * y_pre) AS yy,
    SUM(x1) AS x1_sum,
    SUM(x1 * x1) AS x1x1,
    SUM(x1 * y_pre) AS x1y
FROM historical_panel
WHERE report_date < :experiment_start
GROUP BY report_date;
```

В реальной реализации вместо строковых сумм передаются матрицы `X'X`, `X'y`
и `y'y`, а также число наблюдений. Состав признаков, фильтры популяции,
версия метрики, временной диапазон и дата отсечения сохраняются в `metadata`.

Обязательное правило: если в исходном фрейме есть строка с
`report_date >= experiment_start`, построение завершается ошибкой. Будущие и
post-treatment значения нельзя передавать в prior даже случайно.

## Математика

Для признаков `X` и исторического target `Y` агрегат хранит достаточные
статистики:

\[
X'X, \qquad X'Y, \qquad Y'Y, \qquad n.
\]

Они позволяют вычислять ridge-оценку без восстановления строк:

\[
\hat\beta_\lambda=(X'X+\lambda I)^{-1}X'Y.
\]

Исторический пул задаёт Gaussian ridge prior. Для силы prior `s` его precision
складывается с precision экспериментальной pre-treatment модели. `s = 0`
всегда входит в сетку кандидатов и означает полный отказ от внешнего пула.

Сила prior выбирается по временной проверке на последних исторических месяцах
или на последнем временном блоке доступной экспериментальной панели. В выборе
не участвует текущий post-treatment outcome.

Для каждой строки строится прогноз ожидаемого target `m(X)`. Затем применяется
одинаковая для обеих групп центрированная корректировка:

\[
Y^*=Y-(m(X)-\bar m).
\]

При корректной рандомизации математическое ожидание разности средних остаётся
тем же, а дисперсия может уменьшиться за счёт prognostic signal.

## Зоны A, B и C

Зоны являются отдельными примитивами, а не одним расширением набора признаков:

- `A`: temporal-модель `lag2 -> lag1`, которая строит pre-treatment прогноз;
- `B`: отдельная линейная корректировка по разрешённым in-time признакам,
  обученная только на текущем контроле;
- `C`: отдельная gated-корректировка после проверки пропусков, баланса и
  распределений, также обученная только на контроле.

Вариант `A+B` не переобучает общую модель A на признаках B. Вариант `A+B+C`
добавляет C после B. Поэтому эти варианты являются разными полными
пайплайнами и должны иметь разные строки в отчёте.

## Диагностика и ограничения

Трансформер возвращает выбранную силу prior, effective prior sample size,
ошибку временной проверки, ошибку модели без prior, признак отклонения prior и
описание использованных зон. При сильном несовпадении пула и эксперимента
сетка может выбрать `s = 0`; это не ошибка, а защитный результат prior
discounting.

При небольшом числе месяцев prior нельзя считать независимой обучающей
выборкой. Его преимущество нужно проверять отдельными семействами синтетики:
совпадающий пул, умеренный сдвиг, сильный mismatch и дрейф связи признаков с
target.

## Сложность и хранение

Построение сводки выполняется одним агрегированием по исходному фрейму.
После этого подбор коэффициентов работает по числу признаков и месячных
агрегатов, а не по числу строк большого пула. Для сериализации предусмотрены
JSON и Parquet. В обоих форматах не должны сохраняться пользовательские
идентификаторы.

## Статус

Все три варианта реализованы и участвуют только в RCT-гонке режима
`panel_prior`. Они не являются observational-оценщиками и не запускаются в
будущей observational-гонке.
